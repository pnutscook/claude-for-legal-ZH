# 一般服务与委托合同审查层

本层处理一方委托另一方完成专业工作并交付成果的合同。它不假定对方是软件供应商，也不把政府主体自动当作一般采购方。

## 运行前提

1. 读取 `~/.codex/plugins/config/claude-for-legal-zh/commercial-legal/PRACTICE.md` 和 `commercial-legal:quality-gate`。
2. 确定合同角色：委托方/受托方，以及用户代表哪一方。无法确定时先询问。
3. 提取合同名称、项目背景、成果类型、合同金额、签约主体、附件及被引用但未提供的文件。
4. 如存在行政机关、事业单位、财政资金、征收补偿、政府购买服务、政府采购或审批依据等信号，叠加 `public-sector-contract-overlay`。

## 核心审查清单

| 检查项 | 必须确认的内容 | 常见修改方向 |
|---|---|---|
| 主体与授权 | 名称、统一社会信用代码、签署授权、项目权限 | 补授权依据、签约代表权限和附件清单 |
| 服务范围 | 工作内容、边界、排除事项、配合义务 | 将模糊的“按要求”拆为任务与配合清单 |
| 成果与标准 | 报告/交付件、形式、份数、依据、可接受标准 | 增加成果清单、质量标准、补正机制 |
| 时间与里程碑 | 启动条件、中期节点、最终交付、顺延条件 | 改为客观日期/天数及书面变更机制 |
| 费用与支付 | 计价口径、税费、发票、支付触发、结算资料 | 绑定成果验收与合规付款材料 |
| 验收与异议 | 验收主体、期限、异议、复核、默认效果 | 明确验收不等于免除瑕疵责任 |
| 变更与追加 | 范围变化、费用/工期调整、批准人 | 仅书面批准的变更产生额外费用 |
| 保密与数据 | 文件资料、个人信息、保存/返还、披露范围 | 限定用途并设置返还/删除要求 |
| 违约与终止 | 延误、质量缺陷、单方终止、结算 | 建立对等责任与未完成成果结算 |
| 争议解决 | 法律适用、法院/仲裁机构表述是否确定 | 避免“仲裁或诉讼”二选一不明 |

## 输出

输出单一审查备忘录，必须包含：

1. **路由记录：** `一般服务/委托合同审查`，并说明是否叠加公共部门层。
2. **结论：** `可继续谈判 / 补材料后复核 / 应上报 / 暂不签署`。
3. **风险表：** 风险等级、原文定位或缺漏、问题、依据来源、修改建议、上报对象。
4. **待补材料：** 被引用但未提供、权限或结算所需文件。
5. **可协商修改建议：** 对高风险和中风险项给出可直接替换或加入的条款表述。

不得因为合同金额低而略过主体权限、支付触发、成果验收或争议解决审查。
