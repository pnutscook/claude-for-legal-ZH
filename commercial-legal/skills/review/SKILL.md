# review
根据审查指引审查合同。从标题、当事人、资金与项目背景识别协议结构和叠加风险，选择适用审查层；如 `confirm_routing` 启用则在继续前与用户确认。

## 指令

1. **加载审查指引和质量门槛。** 如果存在占位符，停止并提示运行 `commercial-legal:cold-start-interview`。同时读取 `## 审查偏好` → `confirm_routing`，并执行内部 `commercial-legal:quality-gate`。

2. **获取协议：** 从文件路径、云文档链接、合同管理系统ID或粘贴文本获取。

3. **读取文件结构与交易角色。** 提取主协议标题、当事人、用户代表方、项目背景、价格/资金来源及全部展示件/附件标题。标题只是路由信号之一；合同主体和交易目的可覆盖标题给出的初步分类。

4. **根据文件结构选择技能。**

   | 文件、主体或背景信号 | 审查层 |
   |---|---|
   | 保密协议、NDA、保密协议书（作为*主*协议） | **保密协议审查** |
   | 软件/货物/平台等供应商采购主协议 | **供应商协议审查** |
   | 订阅、SaaS、云服务、带自动续约的订单、带周期性费用的软件许可 | **SaaS审查**（叠加于供应商协议审查之上） |
   | 数据处理协议、DPA（作为展示件或独立文件） | 注记供**供应商协议审查**→数据保护部分 |
   | 咨询服务、委托协议、评估委托、项目服务、非软件专业服务 | **一般服务与委托合同审查层** |
   | 行政机关/事业单位、财政资金、政府购买服务、政府采购、征收补偿、安置或公共项目 | 在基础审查层之上叠加**公共部门合同审查层** |

   多个层可适用。常见组合：评估委托 + 人民政府作为委托方 → 一般服务与委托合同审查层 + 公共部门合同审查层；MSA + DPA展示件 → 供应商协议审查，附DPA注记。

   如果合同是补偿、安置或其他可能体现行政管理目标的协议：加载公共部门层，标记“可能涉及行政协议属性，需专项核验”，不得从通用商事合同路由直接作出定性结论。

5. **如果启用，确认路由。** 如果 `confirm_routing` 为 `true`：

   ```
   我将按以下方式审查：[合同分类]；基础审查层：[技能]；叠加检查：[如有]。
   
   已识别文件：
   - [主协议标题] → [技能]
   - [展示件A标题] → [如何处理]
   
   是否正确？（是/否——或告诉我哪里不对）
   ```

   等待确认。如果 `confirm_routing` 为 `false`：无声继续。

6. **运行技能。** 完全执行每个技能的工作流。如多个技能适用，依次运行并将输出整合为单一备忘录。

7. **检查上报：** 如果任何问题超出审查者权限，调用**上报标注器**路由并起草上报说明。

8. **提供后续操作：** 给业务/项目负责人的利益方摘要、逐项修改建议或带修订痕迹的 `.docx`、待补权限/审批/结算材料清单、合同管理记录创建，以及适用时加入续约登记册。

## 示例

```
commercial-legal:review vendor-msa.pdf
commercial-legal:review 房屋评估委托合同.docx
commercial-legal:review https://drive.google.com/file/d/ABC123
commercial-legal:review
[粘贴协议文本]
```

## 输出

按适用审查层格式输出完整审查备忘录。顶部记录合同分类、双方角色、基础审查层、叠加检查层和法源核验状态。逐条列出原文定位或缺漏、风险、依据、具体修改建议、待补材料与具名审批人。
